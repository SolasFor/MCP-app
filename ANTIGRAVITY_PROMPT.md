## 1. Единый источник прав
Изучи app/ui/pages/security_page.py, clients_page.py, app/ui/oauth_execution_dialogs.py (ClientPermissionsDialog), oauth_clients_dialog.py, backend/oauth_execution.py (ExecutionApprovals, effective_policy_for, active_temporary_grants, client_tool_policy), oauth_store.py, tool_registry.py (allowed_tools/authorize_call), tool_permissions.py, backend/server.py (_live_client_authorizer), desktop policy, workspace/server/device/gateway/extension/task policies, execution_audit.py и существующие audit/log stores, Local Admin API (backend/automation/admin_api.py, app/core/admin_client.py).
Не вводи второй реестр OAuth/прав и не дублируй enforcement в UI. Общий backend read-only evaluator/снимок эффективных прав должен использовать те же policy primitives, что реальный tools/list, tools/call и resource-specific enforcement. Не симулировать доступ владельца при расчёте для клиента. Различать registration/approval, действительный токен и scopes, default/custom profile, permanent/temporary grant, tool allow/deny, global switches, emergency stop, desktop view/control, issuer/origin и resource-specific grants/ACL. Учитывать существующий приоритет deny/allow/temporary grants строго по реальному контракту. Если данных недостаточно, показывать «условно доступно»/«неизвестно» с причинами, не выдавать каталог за гарантированное право выполнить любую команду. Не подменять настоящий scopes широким synthetic scope. Снимок без токенов и секретов; не создавать новые OAuth grants ради просмотра.
Сохранить Safe, Allowlist, Full Access и существующие профили, индивидуальные белые списки, временные разрешения, токены/refresh families, OAuth clients, DPAPI, legacy bearer semantics. Full Access не sandbox и не требует дополнительного подтверждения каждого разрешённого вызова. Новые ресурсы deny-by-default согласно N03–N05. Не перезаписывать старые настройки, пустой allowlist/allowed_clients трактовать по фактической схеме, не расширять scope при refresh или отсутствии/порче данных.

## 2. Интерфейс центра безопасности
Развить существующую вкладку «Безопасность», без нового основного раздела навигации. Компактные панели/вкладки внутри страницы:
- Обзор: состояние аварийной остановки, режим по умолчанию, Computer Use view/control, количество одобренных клиентов, Full Access, активные временные grants, важные предупреждения; если backend недоступен — stale/unknown, не зелёный фиктивный статус.
- Клиенты и права: выбор клиента, его профиль и источник (наследование/override), срок временных grants, доступность по инструментам и категориям, поиск/фильтр (разрешено/условно/запрещено), причины, ресурсные ограничения. Не показывать содержимое секретов, полные команды с credentials или токены. Переиспользовать ClientPermissionsDialog и AI-клиенты; сохранять страницу «AI-клиенты» для регистрации и управления OAuth, общие контроллеры и deep-link вместо дублирующей записи.
- События: последние подключения/авторизации/отказы/изменения прав/отзывы/аварийная остановка, отметка времени, клиент, категория, результат, безопасная причина; фильтр и ограниченный список. Отличать OAuth token issued, authenticated request, last activity и фактическое соединение (не обещать постоянную сессию HTTP). Нет событий — «нет данных», не выдумывать историю.
- Действия: переход к редактированию прав, отзыв клиента или временного grant, сброс override только по явному действию, аварийная остановка и её снятие через существующий механизм. Показывать scope и последствия перед отзывом/расширением прав, только если действительно меняются права. Не добавлять кнопку «Остановить Computer Use»; выключение разрешения должно блокировать следующие вызовы. Не дублировать уже имеющиеся действия.
Минималистичный компактный UI по DESIGN.md: RU/EN, Dark/Light/System, DPI 100/125/150% (по возможности 175/200), 800x540 и 1366x768, keyboard/focus, длинные названия, empty/error states, контекстные меню там, где уместны. Асинхронное обновление с bounded worker/cancellation, без блокировки Qt event loop; UI refresh/retranslate/theme не записывают policy. Не перестраивать все остальные страницы, не начинать N08/N09.

## 3. Backend, отзыв прав и аудит
Обеспечить owner-only чтение/изменение административных данных через уже защищённый loopback Admin API или существующий безопасный локальный механизм. Не публиковать административные endpoints через tunnel/MCP, не расширять список инструментов и их публичные схемы. Повторно использовать guard от N01/N03, проверять origin/Host/loopback/auth и реальное разделение OAuth/owner; не доверять строке client_id=owner, UI или клиентским полям профиля. Проверить admin read/write errors fail closed, не логировать admin token. Если backend недоступен, только явно помеченный offline read-only snapshot; никакой скрытой смены разрешений и фиктивного успеха.
Использовать существующие transactions SQLite и atomic settings. Изменение конкретного поля не теряет параллельные изменения; stale/conflict обновляет preview, rollback при ошибке. Переиспользовать реальные revoke_client/revoke_temporary_grant и execution/desktop emergency stop. После отзыва/истечения или downgrade следующие calls и queued/restarted/scheduled dispatch проверяют актуальные права; проверить N03 server/workspace, N05 SSH/SFTP и Gateway/Extensions/Computer Use. Не обещать остановку уже выполненных side effects; для активных задач показать фактическую семантику отмены и использовать существующий cancellation только где поддерживается. Не убивать независимые пользовательские процессы.
Отображение tool inventory согласовать с реальным tools/list и authorize_call; глобальные и resource-specific ограничения применять на dispatch. Показывать доступные категории ресурсов (workspace/server/device/gateway/extension) и причины условности; глубокий редактор Gateway tool rights остаётся N09. Не переписывать существующие subsystems.
Аудит: переиспользовать защищённые журналы/ExecutionAudit и существующие события, добавить только недостающие структурированные события lifecycle/security. Ограничить размер записи/строк, retention/rotation, число событий на страницу, объём читаемых данных и время. Redact до persistence/UI; не хранить пароль, токен, auth header, private key, command output или полный URL с credentials. Sanitize CRLF/control chars; metadata whitelist. Не передавать историю наружу. Отсутствие события или ошибка чтения — явная диагностика, не синтетическая запись. Сохранить историю существующих логов и ACL. Не добавлять пользовательские backup-функции.
