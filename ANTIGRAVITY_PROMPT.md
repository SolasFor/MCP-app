## 1. Архитектура и миграция без потерь
Сохранить один авторитетный реестр managed servers и существующий backend lifecycle. Связь workspace → несколько серверов через существующие стабильные IDs/имена, без копирования профилей или процессов. Уточнить существующий контракт идентификаторов; если нужна миграция, версионировать только необходимые данные, атомарно и идемпотентно. Не связывать автоматически по совпадению имени/пути; неоднозначные, осиротевшие и непривязанные профили показать в общей секции Workspaces, не удалять. Не создавать фиктивный workspace с широкими правами. Проверить дубликаты, отсутствующие ссылки, многократные связи, rename, удаление workspace (unlink, не удаление серверов), удаление сервера с ссылками, прерывание миграции, повторный запуск, конкурентную запись GUI/backend, совместимость с данными v1.0.2 и N02. Никакого автозапуска или остановки при миграции, никаких изменений независимых процессов без явного действия владельца.
Сохранять IDs, пути, cwd, аргументы, env/secret refs, DPAPI, ACL, min_profile, allowed_clients, client overrides, dependencies, readiness, stop policies, controlled/independent semantics, logs, task links, history, settings и OAuth grants. Не печатать значения секретов. Не расширять BackupManager; техническая транзакционность миграции допустима.

## 2. Интерфейс
Workspaces — единый пункт навигации: список проектов, детали выбранного проекта, секция серверов/процессов внутри проекта и общая секция непривязанных профилей. Переиспользуй существующие виджеты Server Manager либо выдели общие компоненты, не дублируй store/controller. Сохранить создание/редактирование/удаление профиля, привязку/отвязку, templates, start/stop/restart, readiness, logs, metrics, dependencies и команды тестов/сборки через TaskManager с историей. Операции и destructive actions обозначать явно, статус/ошибки честные, управление неблокирующее; не обещать несуществующие метрики. Остановить/удалить — разные действия; отвязка не останавливает процесс. Не добавлять обязательных подтверждений обычных действий Full Access; независимые процессы не усыновлять автоматически.
Компактный минималистичный дизайн по DESIGN.md, переиспользовать токены и текущие компоненты, RU/EN, Dark/Light/System, DPI, keyboard/focus, доступность, контекстные меню где уместны. Пустые/ошибочные/загружаемые состояния, длинные имена, 1366x768 и масштаб 100/125/150%. Не менять стек. Не реализовывать мастер N04.
Удалить отдельный пункт «Серверы» только после подтверждения полной функциональной эквивалентности внутри Workspaces, включая непривязанные профили. Согласовать sidebar, shortcuts, command palette, deep links/старые persisted page keys (безопасный redirect в Workspaces), меню и документацию. Не удалять backend tools или публичные schemas.

## 3. Права и безопасность
Для связанных операций проверять пересечение актуальных workspace/server/task permissions и глобального профиля; отсутствие разрешения одного слоя означает отказ. Не расширять scope клиента при привязке, миграции или удалении workspace. Сохранить семантику существующих standalone server tools и трех профилей Safe/Allowlist/Full Access, не вводить sandbox для произвольного Full Access. Проверять каждый backend-вызов и повторную попытку, в том числе прямой вызов MCP в обход GUI, revoked OAuth, emergency stop и смену профиля. Не доверять только UI, не принимать чужой workspace_id/server_id/command как авторизацию. Проверить правила нескольких связей, зависимостей и предотвращение confused-deputy; не запускать недоступный dependency через разрешённый сервер. Не обходить path security, не выполнять обнаруженные hooks/scripts. Не путать managed server с Gateway или remote devices. Не менять токен владельца, OAuth storage, tunnel settings и существующие разрешения.
N02 production gates неизменны: пустые trust roots/publisher pins, auto-install и boot-recovery BLOCKED, installed без доверенного rollback BLOCKED; не включать signing или обновление в рамках N03. Отдельная приёмка cryptographic integrity восстанавливаемого portable-пакета до исполнения и power-loss recovery требуется до включения production.
