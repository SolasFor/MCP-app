## Содержание этапов

### N00–N01. Подготовка и аудит
Синхронизировать ветку с main без потерь. Проверить окружение и инструменты по docs/antigravity-workflow.md; сохранить локальные пользовательские файлы. Аудит по docs/maintenance-audit.md: воспроизведение дефектов, ACL/DPAPI/OAuth, права, протокол, процессы, UI, packaging. Сначала baseline и воспроизводимые P0/P1, затем минимальные исправления с тестами. Не повторять исторические этапы целиком. Не запускать новую функциональность до окончания подготовки.

### N02. Автообновление
Существующий StagedUpdater не равен безопасному установщику. Реализовать проверку стабильных релизов в фоне, настройки проверки/скачивания/установки при явном завершении, прогресс/ошибки, changelog, проверку подписанного манифеста и бинарника, отдельный updater, корректное ожидание активных операций, staging, selftest, rollback. Поддержать installed и portable (либо явно заблокировать неподдержанный формат с ручным способом). Не заменять файлы работающего процесса; не менять пользовательские данные. См. docs/auto-update.md. Автоустановка выключена по умолчанию до реального доверенного signing и подтверждённой приёмки.

### N03. Серверы → Workspaces
Убрать отдельный пункт «Серверы» только после миграции всех профилей и доступности управления из Workspaces. Сохранить Server Manager, MCP tools, schema, IDs, секреты, ACL, dependencies, controlled/independent semantics. Привязка один workspace — несколько процессов; явно непривязанные профили доступны в общей секции Workspaces, не удаляются. Внутри проекта запуск/остановка/restart, readiness, logs, metrics, команды тестов/сборки через TaskManager и история. Никакого автоматического расширения scope клиента; пересечение workspace/server/task прав, проверить каждый backend-вызов. Не переносить независимые процессы без подтверждения.

### N04. Мастер Workspaces
Выбор каталога или обнаружение в выбранной пользователем директории; read-only анализ Git, package.json/lockfile, pyproject.toml/requirements, venv, runtime, Docker Compose, scripts, порты/entrypoints. Предпросмотр предложенных конфигов и команд, изменения вручную, проверка путей, дубликатов и доступов. Не исполнять project hooks, install, build, npm scripts или код проекта на этапе обнаружения; не искать секреты, не импортировать env secret values. Запуск только после подтверждения доверия и необходимых прав. Примеры Python/Node/Next.js, пустой/неоднозначный проект, монорепо, невалидная конфигурация.

### N05. Мастер SSH
Пошагово: ручной адрес, импорт явных Host из ~/.ssh/config, ограниченное обнаружение на явно выбранной доверенной сети или Tailscale (при наличии CLI и разрешении); проверка TCP, host-key fingerprint, авторизация, ОС, выбор прав, итоговая диагностика. Не AutoAddPolicy, не доверять ssh-keyscan без независимой сверки, не сканировать сеть без явного согласия, не включать sshd/брандмауэр на целевом устройстве автоматически. Предложить инструкции Windows/Linux для SSH, ключей и known_hosts; генерировать ключ только с согласия, не перезаписывать существующий, не отправлять приватный ключ. Импорт без расширения прав. Секреты только SecretStore. Без автоматического sudo/UAC.

### N06–N07. Безопасность и соединения
Центр безопасности: effective rights, client-specific tool inventory, журнал событий/последних подключений, предупреждения, revoke; не обещать sandbox для full. Реальный контроль backend, deny-by-default, не перезаписывать права при UI refresh. Восстановление: health, sleep/network change, DNS, bounded backoff/jitter, отмена при ручной остановке; не создавать новые публичные маршруты, не переиспользовать OAuth между разными origin; уведомление при смене Quick URL.

### N08–N09. Мониторинг и Gateway
Метрики CPU/RAM, запросов, latency, ошибок, клиентов и активных задач с ограниченными буферами и минимизацией данных; главная — компактный status overview с навигацией, без ложных live-значений. Gateway: существующий мастер улучшать, импорт/дедупликация, проверка совместимости/protocol, права на отдельные tools и client scopes, live revoke; не автоматически запускать импортированный STDIO или передавать secrets. Не дублировать существующие функции.

### N10–N12. Устройства, расширения, автоматизация
Windows/Linux: capability-based OS detection, реальные метрики/службы для соответствующей ОС, read/write SFTP с canonical path, symlink/root/quota проверками и fail-closed для неизвестных платформ, безопасное подтверждение mutating операций через права. Не обещать удалённый GUI Computer Use. Расширения: версии/категории/метаданные, trusted provenance, проверка подписей или pin, права, update/rollback; отдельный процесс не OS sandbox. Автоматизация: визуальный редактор графа/последовательностей, проверка циклов/типов, условия, bounded retries, отмена, журнал, актуальная авторизация каждого шага. Не запускать неизвестные side effects из шаблонов.

### N13. Выпуск
Полная CI-матрица, security audit, UI RU/EN Dark/Light/System и DPI, реальные smoke tests с отдельными тестовыми профилями, Windows setup upgrade/uninstall, signed updater positive/negative/rollback tests, SBOM + SHA256SUMS, README/changelog/release notes. Не менять gate или подделывать результаты. Релиз только с отдельного разрешения.

## Не входит в scope
Новые функции резервного копирования не нужны. Существующий BackupManager сохраняется без расширения; техническая копия файлов для безопасной миграции/rollback обновления не является новой функцией бэкапа. Не переписывать стек, не добавлять платные сервисы, не запускать релиз или внешние изменения без разрешения. Общие критерии: docs/acceptance-criteria.md.
