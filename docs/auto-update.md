# Безопасное автообновление — N02

## Реализованная архитектура (`app/updater/`)
- **`app/updater/models.py`**: строгий SemVer (`X.Y.Z`, prerelease/dev отклоняются на `stable`), канонический JSON-манифест `schema_version=1` без лишних полей (`public_key`, `trusted_keys`, `url`, `download_url` строго отвергаются), журнал транзакций `UpdateTransaction` (`PREPARED` -> `BACKING_UP` -> `SWAPPING` / `INSTALLING` -> `VERIFYING_NEW` -> `COMMITTED` | `ROLLING_BACK` -> `ROLLED_BACK` | `FAILED`), персистентное состояние `UpdaterPersistentState` (`highest_seen_version` против downgrade/replay в `%APPDATA%\MCPApp\updates\state.json` через `atomic_write_json(..., restrict_acl=True)`).
- **`app/updater/trust.py`**: встроенные корни доверия `PRODUCTION_TRUST_ROOTS`, список отзыва `PRODUCTION_REVOKED_KEY_IDS`, ротация с окнами `not_before`/`not_after`, проверка отсоединённой подписи Ed25519 по каноническим UTF-8 байтам манифеста и нативная Windows-проверка Authenticode через `wintrust!WinVerifyTrust` + `crypt32!CryptQueryObject` (SHA-1 отпечаток подписанта). Пока `PRODUCTION_TRUST_ROOTS` пуст, автоустановка строго заблокирована (`MISSING_TRUST_ROOTS`); тестовые ключи никогда не поставляются в продакшн.
- **`app/updater/network.py`**: обращения разрешены строго по HTTPS к официальному репозиторию `SolasFor/MCP-app` и pinned-хостам GitHub (`api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`), не более 3 редиректов со сбросом `Authorization` между хостами, лимит 1 МиБ на метаданные, запрет `draft`/`prerelease`, запрет парсинга URL из Markdown-тела релиза, потоковая загрузка с отменой и удалением временного файла при несовпадении размера/SHA-256.
- **`app/updater/staging.py`**: проверка свободного места (`DEFAULT_DISK_RESERVE_BYTES = 150 МиБ`), жёсткая распаковка portable ZIP (zip-slip, UNC/drive-пути, NUL-байты, POSIX-symlink, DOS reparse point `0x400`, NTFS case-collision дубликаты, zip-bomb по числу файлов/размеру/степени сжатия, запрет `token.json`/`settings.json`/`schedules.json`/`oauth/`/`secrets/` и корневых скриптов), private ACL, прямая привязка ожидаемой карты хешей к проверенному подписанному ZIP (`verify_portable_zip_and_compute_map`) и строгая биекция без пропущенных или лишних файлов (`reverify_staged_bundle`, отклоняет `None`/`{}`/reparse точки) на `staged_dir` и на `candidate_dir` непосредственно перед заменой.
- **`app/updater/detector.py`**: раздельное определение режимов `dev` (`DEV_MODE`), `installed` (`unins000.exe`+`.dat` или `HKCU` Uninstall, проверка доступности записи без elevation и криптографически проверенного кэша отката через `verify_cached_rollback_bundle` — подписанный манифест + размер/SHA-256 + Authenticode-отпечаток, иначе `installed` автообновление остаётся `BLOCKED` с `NO_ROLLBACK_CONTRACT`), и `portable` (проверка прав на каталог и родителя, блокировка при посторонних файлах `FOREIGN_FILES_IN_INSTALL_DIR`).
- **`app/updater/helper.py`**: внедеревый процесс `MCPApp.exe --apply-update` из `%APPDATA%\MCPApp\updates\helper_run\<tx_id>` с `__COMPAT_LAYER=RunAsInvoker`. Helper не доверяет `plan.json` в части хешей, отпечатков, отключения Authenticode или `highest_seen_version`: он самостоятельно проверяет `TrustPolicy` (немедленный выход `7` при пустом `PRODUCTION_TRUST_ROOTS`), подписанный `update-manifest.json` + `.sig`, срок и отзыв ключа, защиту от downgrade по `state.json` и реальной версии `MCPApp.exe` в `install_dir`, одноразовый handoff-токен (`hmac.compare_digest` + TTL), одноразовость `tx_id` в `consumed_handoff_ids` с удалением `plan.json` под `.updater.lock`, обязательный завершённый `parent_identity`, допустимость целевой директории (запрет UNC/системных/корневых/home/data/reparse-путей) и единый fail-closed контроль активных операций по `app.paths` (`tasks/tasks.sqlite3`, `.automation.lock`, живые запуски `automation/active_runs.json` по PID+`create_time`, строгая валидация схемы `{"version": 1, "runs": [...]}` в `automation/history.json`, мьютекс `MCPApp-Running` для `installed`, процессы внутри `install_dir`). Для portable-замены `COMMITTED` финализируется до удаления `.MCPApp-old-<tx_id>`; для `installed` проверяются хеш/Authenticode установщика отката и версия после отката (`FAILED` при сбое).
  - **Безопасный boot-recovery (`recover_interrupted_update_on_boot` и `app/gui.py`)**: в dev-режиме (`not frozen`) пропускается; в frozen-режиме привязывается строго к `install_dir = parent(realpath(sys.executable))`, блокируется (`UpdateState.BLOCKED` без удаления данных) при пустом `PRODUCTION_TRUST_ROOTS`, отсутствии/ошибке подписанного манифеста, повреждённом `state.json`, некорректном состоянии транзакции, несовпадении `install_dir`, несоответствии имени `.MCPApp-old-<tx_id>` или наличии symlink/reparse-точек; перед присвоением `ROLLED_BACK` восстанавливает через временное переименование `.MCPApp-displaced-<tx_id>` и проверяет `--version`/`--selftest`/`--headless /health == 200` восстановленного пакета (при провале возвращает исходную рабочую копию и сохраняет резервную копию). Физическое ограничение: при потере питания ровно в момент переименования, когда `install_dir` временно отсутствует до `candidate_dir.replace(install_dir)`, основной `MCPApp.exe` не может стартовать из `install_dir` до ручного переименования `.MCPApp-old-<tx_id>` → `MCPApp` (или внедеревого helper).
- **Сборка и манифест (`tools/release_manifest.py`, `packaging/build.ps1`, CI)**: канонический `update-manifest.json` генерируется на Windows-сборке и валидируется в `.github/workflows/rc-windows.yml` и `build.yml`; подпись `.sig` создаётся только при наличии защищённых секретов релиза.
- **Совместимость**: `backend/automation/backup_updater.py` (`BackupManager`, `StagedUpdater`) сохранён без расширения функций резервного копирования.

## Процедура включения продакшн-доверия (для владельца)
1. Сгенерировать root/release пару Ed25519 в защищённом offline/CI-окружении (приватный ключ хранить только в secrets protected release environment, никогда не коммитить).
2. Добавить `TrustRootKey(key_id, public_key_b64, not_before, not_after)` в `PRODUCTION_TRUST_ROOTS` и отпечатки сертификата Authenticode в `PRODUCTION_PUBLISHER_THUMBPRINTS` внутри `app/updater/trust.py`.
3. Для ротации добавить новый `TrustRootKey` с перекрывающимся окном `not_before`/`not_after`, а при компрометации перенести скомпрометированный `key_id` в `PRODUCTION_REVOKED_KEY_IDS`.
4. Первый переход с неподписанной сборки `1.0.2` в подписанную ветку выполняется вручную владельцем (доверие никогда не инициализируется из загруженного манифеста).

## Обязательный production gate после merge N02
N02 MERGED (PR #38, 4b9bedb) означает приёмку кода, не допуск автоустановки. PRODUCTION_TRUST_ROOTS и PRODUCTION_PUBLISHER_THUMBPRINTS остаются пустыми до отдельного решения владельца; production auto-install и автоматический boot-recovery BLOCKED (MISSING_TRUST_ROOTS), installed без криптографически проверенного rollback — BLOCKED (NO_ROLLBACK_CONTRACT). До включения production требуется отдельная приёмка инфраструктуры Ed25519/Authenticode, проверка криптографической целостности именно восстанавливаемого portable-пакета до запуска его бинарника, проверка rollback при прерывании и потере питания (включая отсутствие install_dir между rename). Самопроверка/health не заменяют криптографическую проверку. Первый переход с неподписанной 1.0.2 — вручную в доверенную сборку. Не включать production-ключи/автоустановку в N03–N13 без отдельной авторизации и успешной приёмки этих gates; не выдавать BLOCKED/NOT_RUN за PASS.
