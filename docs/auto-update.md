# Безопасное автообновление — N02

## Реализованная архитектура (`app/updater/`)
- **`app/updater/models.py`**: строгий SemVer (`X.Y.Z`, prerelease/dev отклоняются на `stable`), канонический JSON-манифест `schema_version=1` без лишних полей (`public_key`, `trusted_keys`, `url`, `download_url` строго отвергаются), журнал транзакций `UpdateTransaction` (`PREPARED` -> `BACKING_UP` -> `SWAPPING` / `INSTALLING` -> `VERIFYING_NEW` -> `COMMITTED` | `ROLLING_BACK` -> `ROLLED_BACK` | `FAILED`), персистентное состояние `UpdaterPersistentState` (`highest_seen_version` против downgrade/replay в `%APPDATA%\MCPApp\updates\state.json` через `atomic_write_json(..., restrict_acl=True)`).
- **`app/updater/trust.py`**: встроенные корни доверия `PRODUCTION_TRUST_ROOTS`, список отзыва `PRODUCTION_REVOKED_KEY_IDS`, ротация с окнами `not_before`/`not_after`, проверка отсоединённой подписи Ed25519 по каноническим UTF-8 байтам манифеста и нативная Windows-проверка Authenticode через `wintrust!WinVerifyTrust` + `crypt32!CryptQueryObject` (SHA-1 отпечаток подписанта). Пока `PRODUCTION_TRUST_ROOTS` пуст, автоустановка строго заблокирована (`MISSING_TRUST_ROOTS`); тестовые ключи никогда не поставляются в продакшн.
- **`app/updater/network.py`**: обращения разрешены строго по HTTPS к официальному репозиторию `SolasFor/MCP-app` и pinned-хостам GitHub (`api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`), не более 3 редиректов со сбросом `Authorization` между хостами, лимит 1 МиБ на метаданные, запрет `draft`/`prerelease`, запрет парсинга URL из Markdown-тела релиза, потоковая загрузка с отменой и удалением временного файла при несовпадении размера/SHA-256.
- **`app/updater/staging.py`**: проверка свободного места (`DEFAULT_DISK_RESERVE_BYTES = 150 МиБ`), жёсткая распаковка portable ZIP (zip-slip, UNC/drive-пути, NUL-байты, POSIX-symlink, DOS reparse point `0x400`, NTFS case-collision дубликаты, zip-bomb по числу файлов/размеру/степени сжатия, запрет `token.json`/`settings.json`/`schedules.json`/`oauth/`/`secrets/` и корневых скриптов), private ACL, а также повторная проверка TOCTOU (`reverify_staged_bundle`) непосредственно перед заменой/запуском.
- **`app/updater/detector.py`**: раздельное определение режимов `dev` (`DEV_MODE`), `installed` (`unins000.exe`+`.dat` или `HKCU` Uninstall, проверка доступности записи без elevation и наличия кэшированного установщика отката — иначе `NO_ROLLBACK_CONTRACT`), и `portable` (проверка прав на каталог и родителя, блокировка при посторонних файлах `FOREIGN_FILES_IN_INSTALL_DIR`).
- **`app/updater/helper.py`**: внедеревый процесс `MCPApp.exe --apply-update` из `%APPDATA%\MCPApp\updates\helper_run\<tx_id>` с `__COMPAT_LAYER=RunAsInvoker`, проверкой одноразового handoff-токена (`hmac.compare_digest` + TTL), файловой блокировкой `.updater.lock` / мьютексом, ожиданием завершения родительского `ProcessIdentity`, проверкой отсутствия активных задач `TaskStore`, атомарной заменой директории с удержанием `.MCPApp-old-<tx_id>` до прохождения пост-проверки (`--version`, `--selftest`, `--headless` `/health == 200`), автоматическим откатом при любой ошибке и восстановлением незавершённых транзакций при старте (`recover_interrupted_update_on_boot`). Пользовательский профиль `%APPDATA%\MCPApp` (`token.json`, `oauth/`, `secrets/`, `settings.json`, расписания N01) никогда не удаляется и не перезаписывается.
- **Сборка и манифест (`tools/release_manifest.py`, `packaging/build.ps1`, CI)**: канонический `update-manifest.json` генерируется на Windows-сборке и валидируется в `.github/workflows/rc-windows.yml` и `build.yml`; подпись `.sig` создаётся только при наличии защищённых секретов релиза.
- **Совместимость**: `backend/automation/backup_updater.py` (`BackupManager`, `StagedUpdater`) сохранён без расширения функций резервного копирования.

## Процедура включения продакшн-доверия (для владельца)
1. Сгенерировать root/release пару Ed25519 в защищённом offline/CI-окружении (приватный ключ хранить только в secrets protected release environment, никогда не коммитить).
2. Добавить `TrustRootKey(key_id, public_key_b64, not_before, not_after)` в `PRODUCTION_TRUST_ROOTS` и отпечатки сертификата Authenticode в `PRODUCTION_PUBLISHER_THUMBPRINTS` внутри `app/updater/trust.py`.
3. Для ротации добавить новый `TrustRootKey` с перекрывающимся окном `not_before`/`not_after`, а при компрометации перенести скомпрометированный `key_id` в `PRODUCTION_REVOKED_KEY_IDS`.
4. Первый переход с неподписанной сборки `1.0.2` в подписанную ветку выполняется вручную владельцем (доверие никогда не инициализируется из загруженного манифеста).
