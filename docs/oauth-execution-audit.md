# OAuth, Cloudflare и локальный аудит выполнения (v0.8.3 RC)

## Пояснения к логам

1. **OAuth.** Промежуточный HTTP-слой больше не сравнивает каждый
   OAuth Bearer-токен с токеном владельца. Валидация токена выполняется
   MCP SDK. Запись `MCP авторизация отклонена HTTP 401/403` появляется
   только после фактического отказа SDK; успешные OAuth-запросы `200`
   и `202` не создают ложного предупреждения «Неверный токен».
   Обычный `HEAD /mcp` без Bearer — ожидаемый discovery-запрос клиента.
2. **Запуск.** Лог отображает OAuth с локальным согласием,
   глобальный режим по умолчанию, число зарегистрированных клиентов,
   размер разрешённых Windows/SSH-списков и путь отдельного журнала.
   Индивидуальные права определяются при каждом запросе и могут
   отличаться от режима по умолчанию. Устаревшие слова `read-only`
   / `execution disabled` для OAuth удалены.
3. **Cloudflare.** `context canceled` — отмена HTTP/SSE-запроса,
   но не доказательство разрыва туннеля. MCP app оставляет оригинальную
   ошибку и показывает однократную информационную подсказку при работающих
   процессах. Если cloudflared сообщает `connection refused` /
   `Unable to reach the origin service`, показывается отдельное
   предупреждение о недоступности локального сервера и адрес проверки
   `http://127.0.0.1:<порт>/health`.

## Аудит Windows и SSH

Файл: `%APPDATA%\MCPApp\server\mcp_execution_audit.jsonl` для Windows
GUI-сборки (путь определяется рабочей папкой запуска сервера).
Отдельный журнал не загружается в Cloudflare.

Каждая строка — JSON с:
- временем в UTC (`at`);
- удостоверенным OAuth `client_id`;
- типом операции (`windows` или `ssh`);
- сценарием доступа (`safe`, `allowlist`, `full`);
- событием `denied`, `started`, `completed` или `failed`;
- SHA-256 отпечатком команды (`command_sha256`), а для SSH — и
  отпечатком хоста (`host_sha256`) и портом;
- случайным `action_id` для сопоставления запуска и завершения;
- кодом завершения и длительностью, если они известны.

**Не записываются** команды и их аргументы открытым текстом,
токены владельца/OAuth, SSH-пароли и имена пользователей, stdout/stderr.
При ошибках аудит пишет тип ошибки в общий журнал, а не конфиденциальные
данные команды.

Используется ротация: активный файл до **2 МиБ** и три резервные копии.
Доступ к папке должен оставаться закрытым для других пользователей
Windows. Отпечаток SHA-256 не заменяет сокрытия секретов для слабых /
легко угадываемых команд, поэтому журнал следует хранить локально.

Это журнал наблюдаемости, **не Windows-песочница**. Полный доступ по-прежнему
позволяет подтверждённому OAuth-клиенту запускать команды без разрешения
каждого вызова. Для надёжного отзыва уже исполняемого процесса требуется
отдельная изоляция; отзыв токена блокирует новые вызовы.
