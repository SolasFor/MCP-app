# Единый неизменяемый OAuth-профиль: Windows + SSH

В этом варианте MCP-app **нет настраиваемых прав для разных OAuth-клиентов**.
После подтверждения владельцем каждый клиент получает один и тот же
набор инструментов:

- `oauth_windows_command` — запросить запуск Windows-программы.
- `oauth_ssh_command` — запросить запуск команды на SSH-хосте.
- `server_info` — безопасный диагностический инструмент, не требующий запуска команд.

Права на произвольные файлы и заметки не существуют. Другие варианты
доступа в окне OAuth-клиентов не предлагаются.

## Почему команда не выполняется автоматически

Windows/SSH-доступ — привилегированная операция. Поэтому после входа по
OAuth инструменты видны, но **никакую команду нельзя запустить**, пока:

1. Владелец на своём компьютере не задаст её **точный** текст в списке
   разрешённых команд. Для SSH также нужен точный SSH-хост.
2. Клиент не отправит запрос этой конкретной команды.
3. Владелец не проверит и не одобрит **именно этот** запрос через локальное
   окно MCP-app.
4. Клиент не повторит тот же вызов с одноразовым идентификатором одобрения.

Это не изменение прав OAuth-клиента: набор инструментов не меняется.
Списки допустимых команд и согласие на каждый запуск — отдельные
обязательные проверки безопасности.

## Как пользоваться

1. Запустите MCP-app и подключите клиент через OAuth.
2. Перейдите в **«Подключение» → «Управление OAuth-клиентами…»**.
   В столбце «Права» увидите `Windows + SSH (фиксировано)`.
3. Откройте **«Разрешённые команды и хосты…»**. Для первого теста
   на Windows добавьте строку `hostname.exe`. Для SSH дополнительно
   задайте точное имя хоста (например, собственный SSH-алиас) и команду
   `uptime`. Пустые списки означают «все действия запрещены».
4. Попросите клиента вызвать `oauth_windows_command` с
   `command="hostname.exe"`. Он получит `approval_id`, но пока
   **не выполнит** команду.
5. Откройте **«Очередь подтверждений…»**, проверьте клиента, точный
   текст команды и цель. Разрешите один раз или отклоните.
6. После разрешения клиент должен повторить **тот же самый** MCP-вызов
   и передать `approval_id`. Он действует 3 минуты, используется
   только один раз и привязан к клиенту и параметрам запроса.
7. Для SSH повторите сценарий с `oauth_ssh_command`, указав
   `host`, `command`, необязательные `user` и `port`.
   Неизвестные SSH host keys отвергаются. Предварительно проверьте
   ключ SSH-хоста вручную и установите доверие в `known_hosts`.

Важная граница: Windows-команды выполняются от имени пользователя,
запустившего MCP-app. Не разрешайте интерпретаторы или программы,
которые могут исполнять произвольный код, если не готовы к этому риску.
Возможность назначать списки команд доступна только владельцу
локального интерфейса; AI-клиент не может их изменить по сети.

## Обработка «context canceled» из Cloudflare

Сообщение `failed to proxy HTTP: context canceled` означает отменённый
запрос и **не обязательно** говорит о разрыве туннеля. При длинных
запросах такое бывает, когда клиент прекращает соединение.

Вместо ожидания одобрения прямо внутри HTTP-запроса MCP-app выдаёт
одноразовый ticket сразу. Поэтому время, пока владелец читает запрос,
не удерживает запрос Cloudflare открытым.

Чтобы диагностировать реальный сбой, сравните:
- `http://127.0.0.1:8000/health` — должен отвечать HTTP 200 с `{"status":"ok"}`.
- `https://<ваш-адрес>.trycloudflare.com/health` — тоже HTTP 200.

Если оба отвечают, но клиент разрывает отдельные MCP-запросы, проверьте
его тайм-аут и поддерживаемый формат транспорта (Quick Tunnel работает
в JSON-режиме без полноценного SSE).

## Ограничения

- Набор OAuth-возможностей фиксирован, но **общее разрешение на выполнение
  без подтверждения не выдаётся**. Это намеренная защита.
- Списки безопасных команд не являются контейнерной изоляцией. Запуск
  происходит с обычными правами Windows-пользователя / SSH-учётной записи.
- После перезапуска с новым `*.trycloudflare.com` адресом OAuth-клиент
  должен заново пройти авторизацию.
- При отзыве OAuth-клиента удаляются его токены и ожидающие действия.
- Приложение и выбранный внешний MCP-клиент ещё должны пройти ручную
  проверку на реальном Windows + Cloudflare после сборки из этой ветки.
