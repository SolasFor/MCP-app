# Постоянное хранение OAuth и управление клиентами (PR-05)

Этот этап продолжает [PR № 8](../README.md): OAuth больше не теряет
регистрации и выданные токены **при перезапуске MCP-сервера с тем же
публичным адресом**.

## Как использовать в Windows

1. Запустите обновлённое приложение и авторизуйте клиент через OAuth как
   обычно (предыдущие подключения PR-04 были только в оперативной памяти,
   поэтому потребуют однократной повторной авторизации).
2. Откройте вкладку **«Подключение» → «Управление OAuth-клиентами…»**.
3. Посмотрите название клиента, статус («Зарегистрирован» или «Разрешён»)
   и дату последнего разрешения.
4. Для удаления выберите строку и нажмите **«Отозвать доступ»**.
   Регистрация клиента и все его OAuth-токены аннулируются немедленно,
   даже если сервер уже запущен.
5. Если клиент пытается использовать старый токен, сервер отвечает 401.
   Для повторного подключения потребуется новая регистрация и согласие.

В этот список не включён общий Bearer-токен владельца. Его можно сменить
в обычных настройках приложения; **смена токена владельца** инвалидирует
OAuth-гранты, когда сервер запустится с новым токеном.

## Где хранятся данные

- `%APPDATA%\MCPApp\oauth\connections.sqlite3` — SQLite-база.
- `%APPDATA%\MCPApp\oauth\connections.key` — ключ шифрования Fernet.
- **Windows:** ключ зашифрован DPAPI для текущего пользователя Windows.
  Регистрационные данные OAuth (в том числе client_secret) шифруются;
  токены доступа и обновления хранятся только как SHA-256 дайджесты
  вместе с зашифрованными метаданными и сроком действия.
- **Linux / macOS (разработка):** Fernet-ключ находится в файле с правами
  0600 внутри каталога 0700, **без аппаратной/OS-keychain защиты**.
  Этот режим следует считать ограниченной защитой для локального тестирования.

Не пересылайте базу и файл ключа. Не редактируйте и не удаляйте `.key`
отдельно от базы: без него зашифрованные данные не восстановятся.

## Ограничение по временным адресам Cloudflare

`https://abc.trycloudflare.com/mcp` и
`https://xyz.trycloudflare.com/mcp` — **разные защищённые ресурсы**.

- При перезапуске бэкенда **с тем же адресом** OAuth сохраняется.
- Когда Quick Tunnel выдаёт **новое доменное имя**, старые регистрации и
  токены для предыдущего `*.trycloudflare.com` удаляются; новый адрес
  требует новой авторизации клиента.
- Для постоянного доступа рекомендуем свой домен и Named Tunnel.
- При изменении пути MCP или токена владельца гранты аннулируются.
- Срок действия access token — 1 час, refresh token — до 7 дней.

Хранилище сохраняет только регистрации и выдаваемые OAuth-токены.
Незавершённые запросы согласия и одноразовые authorization codes остаются
в памяти на несколько минут. Если сервер перезапущен прямо во время
согласия, нужно повторить подключение.

## Безопасность и границы

- Все подтверждённые OAuth-клиенты разделяют один выбранный владельцем
  сценарий: Безопасный (по умолчанию), Белый список или Полный доступ.
  В последних двух команда может выполняться **без дополнительного
  подтверждения каждого вызова**; риск полного режима очень высок.
- Смена режима и списков команд доступна **только в локальном GUI**;
  никаких `/admin`-маршрутов через Cloudflare нет.
  См. [три сценария Windows/SSH](oauth-fixed-windows-ssh.md).
- После отзыва доступа сервер проверяет SQLite при каждом предъявлении
  OAuth-токена; новые вызовы блокируются. Уже выполняемое действие
  может завершиться.
- Пользовательское хранилище не рассчитано на совместный доступ нескольких
  Windows-пользователей или на удалённое распределённое развёртывание.
- Не используйте привилегированные режимы для недоверенных OAuth-клиентов.

## Проверки

CI выполняет unit-тесты SQLite, шифрования, смены владельца,
ротации URL и отзыва из независимого объекта хранилища.
Интеграционный HTTP-тест запускает Uvicorn, регистрирует клиента через OAuth,
получает токены, перезапускает сервер с **тем же адресом и SQLite-файлом**
и проверяет `initialize`, `tools/list`, `tools/call`, refresh/revoke.

Живой Quick Tunnel и GUI Windows нужно дополнительно проверить вручную.
