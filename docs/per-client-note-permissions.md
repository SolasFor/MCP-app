# Индивидуальные разрешения OAuth-клиентов (PR-06)

В этом этапе MCP-app разрешает владельцу вручную выдавать доступ к
**отдельной папке заметок**, не раскрывая Windows-команды, SSH, весь рабочий
каталог, настройки или системные файлы. Каждый клиент управляется независимо.

## Настройка из Windows-приложения

1. Подключите MCP-клиента по OAuth и подтвердите доступ, как в PR-08.
2. Откройте **Подключение → Управление OAuth-клиентами…**.
3. Выберите подтверждённого клиента. По умолчанию оба флажка выключены:
   - **Чтение общих заметок** — инструменты `shared_notes_list`,
     `shared_note_read`.
   - **Запись общих заметок** — инструмент `shared_note_write`.
4. Нажмите **Открыть папку заметок** и поместите туда небольшой .txt/.md
   файл, например `hello.md`. Можно также разрешить клиенту создавать
   заметки самостоятельно.
5. Разрешения применяются к **следующему запросу** без перезапуска MCP app
   и без повторной OAuth-авторизации. Отключите флажок — инструмент исчезнет
   из `tools/list`, а попытка прямого вызова будет отклонена.

Временный каталог на Windows:
`%APPDATA%\MCPApp\shared_notes`.

## Безопасная модель

- Стандартный профиль для нового OAuth-клиента: **только `server_info`**.
- Регистрация DCR без явного согласия владельца НЕ даёт доступа к заметкам.
- Разрешения сохраняются в SQLite для каждого `issuer + client_id`,
  выдаются только уже подтверждённым клиентам и аннулируются при отзыве
  клиента или смене токена владельца.
- Реальный OAuth `AccessToken` из текущего HTTP-запроса, а не заявленный
  моделью `client_id`, определяет разрешения.
- Проверка выполняется на двух уровнях: middleware скрывает запрещённые
  инструменты из `tools/list`, а обработчик повторно проверяет SQLite
  непосредственно перед чтением или записью.
- Общий Bearer-токен владельца не может получить права OAuth-клиента.
- Встроенные Windows shell, SSH и `read_workspace_file`/`write_workspace_file`
  остаются полностью скрыты от OAuth-клиентов.
- Один клиент не получает разрешения другого. Все сессии **одной OAuth-регистрации**
  используют общие разрешения этой регистрации — это не отдельные права
  для пользователей одной внешней платформы.

**Важно:** DCR-название клиента задаёт сам клиент. Оно не является
доказательством его подлинности. При подтверждении проверяйте
redirect URI, а при выборе доступа — доверяйте только известному подключению.

## Ограничения папки

- Только файлы в одной папке, без подпапок и произвольных абсолютных путей.
- Только короткие ASCII-имена с расширением `.txt` или `.md` и текст UTF-8.
- Максимум **32 КиБ на заметку**. Ссылки/симлинки блокируются; запись
  выполняется атомарной заменой файла.
- Нельзя читать `settings.json`, `.env`, SSH-ключи или файлы вне
  изолированной папки.
- На Windows защита от злоумышленной конкурентной подмены файлового
  пути не является полноценным контейнером; **не размещайте общий каталог
  в папке, куда могут записывать другие недоверенные локальные пользователи**.
- На запись по умолчанию действует отдельный явный флажок; прочитать
  содержимое файлов можно только с отдельным разрешением.

## OAuth scope и локальные ACL

Для совместимости с существующими клиентами OAuth scope `mcp:read`
остаётся базовым пропуском к серверу. Разрешения на конкретные заметки,
включая запись в изолированную папку, — **дополнительная локальная ACL**,
управляемая владельцем в GUI, а не новые OAuth-scopes. Это не означает
автоматического повышения прав после установки. Для расширенного доступа
к Windows/SSH потребуются отдельные OAuth-scopes, подтверждение каждого
действия и изоляция; это не реализовано.

## Проверка

1. Подключите OAuth-клиента и вызовите `tools/list`: `server_info`.
2. Создайте `hello.md` в каталоге заметок и включите клиенту чтение.
3. Убедитесь, что `shared_notes_list` и `shared_note_read`
   появились у него, а запись по-прежнему отклоняется.
4. Выключите чтение и включите запись: клиент может создать `draft.md`,
   но не может просмотреть список файлов или прочитать их.
5. Выключите оба флажка: следующий запрос `tools/list` снова содержит
   только `server_info`.
6. Отзовите OAuth-клиента — все его токены перестанут работать.

GitHub Actions проверяет эту последовательность через реальный
HTTP-сервер и через unit-тесты, отдельно на Windows и Linux.
