# Стабильность и безопасность (MCP-app v0.8.6)

Этап 1 закладывает общую инфраструктуру процессов, хранилища секретов, контроля прав
и устойчивости соединений без переписывания приложения целиком.

## Платформенная абстракция (`app/platform/`)

- `app/platform/base.py` определяет интерфейс `PlatformAdapter` и модели
  `ProcessIdentity`, `ProcessJobHandle`, `TerminationReport`.
- `app/platform/windows.py` реализует Job Objects (`KILL_ON_JOB_CLOSE`, опционально
  `BREAKAWAY_OK`), проверку принадлежности процессов по `create_time` (защита от
  PID reuse), DPAPI (`CryptProtectData`), Windows Credential Manager (`CredWriteW` /
  `CredReadW` / `CredDeleteW`), ACL через `icacls`, а также определение OEM/ANSI кодировок.
- `app/platform/posix.py` обеспечивает совместимость на Linux/macOS CI с правами
  `0700`/`0600` (без OS keychain — документировано как ограничение dev/CI-окружения).

## ProcessRunner и ограниченный потоковый вывод (`backend/process_runner.py`, `backend/output_stream.py`)

- **Единый исполнитель:** `oauth_windows_command`, `run_local_command` и
  `ManagedServers` работают через `ProcessRunner` без всплывающего окна консоли
  (`CREATE_NO_WINDOW`).
- **Жизненный цикл:**
  - `controlled` (по умолчанию): отдельный Windows Job Object + проверка
    `ProcessIdentity` + завершение всего дерева дочерних процессов при timeout,
    отмене или остановке.
  - `independent`: для явно независимых GUI-программ (`CREATE_NEW_PROCESS_GROUP |
    CREATE_BREAKAWAY_FROM_JOB`) без kill-on-close владения.
- **Параллельное чтение и квоты:**
  - `stdout` и `stderr` читаются параллельно (`asyncio.gather`) в ограниченный
    кольцевой буфер памяти (`64 KiB` head+tail на поток) и дисковый spool
    (`2 MiB` на запуск, `20 MiB` всего, до 100 файлов, TTL 1 час) с безопасной
    постраничной выборкой (`offset`/`limit`) и декодированием UTF-8 / OEM / ANSI.
- **Квоты и отмена SSH:** ограничены одновременные запросы (`MCP_MAX_IN_FLIGHT`,
  по умолчанию 32), команды (`MCP_MAX_CONCURRENT_COMMANDS`, по умолчанию 8) и
  SSH-вызовы (`MCP_MAX_CONCURRENT_SSH`, по умолчанию 4) в отдельном
  `ThreadPoolExecutor`. Отмена одного SSH-запроса закрывает его транспорт и
  не блокирует остальные вызовы.

### Зафиксированные замеры при большом выводе (Windows 11, Python 3.13)

Тест: дочерний процесс одновременно записал `11 141 460` байт в `stdout` и
`11 141 460` байт в `stderr` (~21.2 MiB суммарно):

- Возвращено в ответе инструмента: по `8 050` символов `stdout` и `stderr` (с маркером обрезки).
- Пиковая трассируемая память Python (`tracemalloc`): `730 350` байт (~713 KiB).
- Занято на диске в spool с учётом квот: `4 194 304` байт (4.0 MiB: по 2 MiB на поток).
- Длительность выполнения: `328` мс, утечки памяти/диска и блокировки каналов отсутствуют.

## Хранилище секретов, миграции и санитизация (`app/core/secret_store.py`, `app/core/redaction.py`)

- `SecretStore` шифрует токен владельца, ключ именованного туннеля (`domain.json`)
  и учётные данные прокси (`proxy.json`) через Fernet + Windows DPAPI (с поддержкой
  Credential Manager). Прежние открытые файлы переносятся прозрачно при чтении.
- `OAuthStore` (версия схемы `2`) выполняет атомарные транзакционные миграции,
  поддерживает индивидуальные белые списки, временные разрешения, флаг аварийной
  остановки и экспорт резервной копии без секретов (`export_redacted_backup`).
- `sanitize_child_env` удаляет `MCP_*`, `MCP_SECRET_TOKEN`, `TUNNEL_TOKEN` и
  прочие внутренние секреты из окружения дочерних команд и управляемых серверов.
- `SecretRedactor` и `RedactingLogFilter` очищают журналы и экспортируемые отчёты
  диагностики.

## Права доступа и аварийная остановка (`backend/tool_registry.py`)

- `ToolRegistry` проверяет права в `tools/list`, при входе в `tools/call` и
  **повторно после ожидания в очереди** непосредственно перед запуском процесса.
- Поддерживаются три профиля (`safe`, `allowlist`, `full`), индивидуальные белые
  списки на клиента и временные разрешения со сроком действия.
- Кнопка **«Аварийная остановка»** немедленно блокирует новые OAuth-вызовы и
  останавливает контролируемые процессы и активные SSH-сессии.

## Реальные ограничения (честное раскрытие)

1. **Полный доступ (`full`) не является Windows sandbox.** Команды исполняются с
   правами текущей учётной записи Windows/SSH; отдельные разрешения инструментов и
   DPAPI не изолируют произвольный код от имени того же пользователя.
2. **Независимые/внешние процессы:** при аварийной остановке процессы,
   запущенные в режиме `independent` или отделившиеся ранее через произвольный
   shell, не гарантируются к автоматическому завершению и честно перечисляются
   в отчёте `unstoppable_processes`.
3. **Подпись Authenticode:** публичного сертификата издателя пока нет;
   автоустановка обновлений остаётся отключённой до подписания доверенным сертификатом.
