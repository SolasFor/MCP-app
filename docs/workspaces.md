# Workspaces & Managed Servers (`v1.0.2` / N03)

MCP-app Workspaces provides the single unified UI and project registry (`%APPDATA%\MCPApp\workspaces\workspaces.json`, schema v2) combining guarded per-project file/Git/task operations with local Server Manager lifecycle control (`%APPDATA%\MCPApp\servers\managed_servers.json`).

## Single Authoritative Server Linkage (`WorkspaceProfile.linked_servers`)
- **Single Runtime & Admin API (`N03-01`, `N03-FINAL-01`)**: When the backend is running, `WorkspacesPage` delegates live server lifecycle/logs/metrics/autostart and workspace task execution to the single authoritative backend via the loopback-only Local Admin API (`LocalAdminClient` → `backend/automation/admin_api.py`). Mutating operations fail closed (`AdminRequestAmbiguousError` on post-dispatch drop/timeout; `AdminBackendUnavailableError` while backend is active) and only fall back to the local runtime when backend is confirmed stopped; read-only polling safely falls back to the reconciled ledger. Across processes and backend restarts, `ServerManager` reconciles `managed_servers.runtime.json` (guarded by `.managed_servers.runtime.lock`) via `ProcessIdentity(pid, create_time)` and propagates `stop_requested` / `run_id` ownership handoffs so local supervisors never re-launch remotely stopped servers, `controlled` processes never double-spawn, and `independent` processes stay trackable across restarts. Closing GUI stops only GUI-owned `controlled` handles.
- **1:N & N:1 Links Without Duplication**: Workspaces reference existing `ServerProfile` IDs via `WorkspaceProfile.linked_servers` (`WorkspaceServerCoordinator` in `backend/workspaces/server_links.py`) without creating a parallel server registry or duplicating DPAPI secrets.
- **Unlinked Servers & `workspace_scoped` No-Widening Guard (`N03-02`)**: Standalone unlinked servers remain visible and manageable in the **Unlinked Servers** tab inside Workspaces. Linking a server to any workspace sets `ServerProfile.workspace_scoped = True`; unlinking the last workspace (`unlink_server`, `set_workspace_servers`) or deleting the workspace (`delete_workspace_preserving_servers`) preserves this guard so non-owner clients never gain implicit standalone access unless the owner explicitly authorizes unscoped access (`set_server_workspace_scoped(..., False)` / GUI toggle).
- **Non-Destructive Unlink & Delete**: Unlinking a server or removing a workspace entry only updates the registries and workspace secrets — it **never** stops or deletes managed server profiles or detached `independent` processes.
- **Transactional Config Updates & Strict Lock Order (`N03-03`, `N03-04`, `N03-FINAL-02`)**: Multi-store mutations (`ensure_migrated`, `link_server`, `unlink_server`, `set_workspace_servers`, `delete_workspace_preserving_servers`, `rename_server`, `delete_server_and_unlink`) acquire locks strictly in order `WorkspaceStore.lock() -> ServerConfigStore.lock() -> AutomationScheduler (.automation.lock) -> ServerManager runtime (.managed_servers.runtime.lock) -> in-memory RLock`, with bounded `cross_process_lock` timeouts on Windows and POSIX and write-ahead journal rollback (`.n03_coordinator_tx.json`) so old `SecretStore` keys are never deleted before durable commit and Automation `schedules.json` server references update atomically on rename. Pending journal recovery validates `schema_version == 1`, exact top-level keys, bounded size, canonical allowlisted config/marker paths, absence of symlinks/reparse points, valid JSON preimages before any write, `servers`-only `created_secrets` absent from the server preimage, and acquires `.automation.lock` before restoring `schedules.json`.
- **Lossless v1→v2 Migration & Fail-Closed Corruption Handling**: Migrating v1.0.2 configs creates `.json.v1.bak` backups and `.initialized` markers with user-private ACLs, preserves all IDs/secrets/permissions, and **never** guesses workspace-to-server associations by `cwd` or name. Corrupt JSON, empty `0`-byte files, missing initialized files, and unknown `schema_version` values fail closed (`ValueError` / `PermissionError`) without overwriting disk files.

## Cross-Layer Permissions & Task History
- **Fail-Closed Live Intersection (`N03-05`)**: Operating on a linked server intersects **Live OAuth Client Approval & Profile ∩ Emergency Stop ∩ Workspace Permissions ∩ ServerProfile (`min_profile`, `allowed_clients`, `workspace_scoped`) ∩ Task Permissions**. Authorization and fresh disk profiles are re-verified immediately before spawning every process step (including after `depends_on` readiness waits), inside `WorkspaceManager.run_workspace_task` pre-dispatch checks, and in `_supervisor_tick` auto-restarts using the originating `workspace_id`.
- **Pre-Launch Confused-Deputy Guard**: Starting a server that declares `depends_on` validates caller authorization on every dependency workspace/server before launching any process.
- **Full TaskManager Parity (`N03-06`)**: Running named workspace commands (`workspace_run_task` or GUI **Run Task**) shares `TaskManager`'s `TaskStore`, `spool_dir`, and `artifacts_dir`, writes redacted `TaskSpec` (`workspace_id`, `workspace_command`) and `result.json` artifacts, supports `task_status`/`task_list`/`task_output`/`task_result`/`task_artifacts`/`task_cancel` (including DB `cancel_requested` polling and `CancelledError` cleanup) and workspace-aware `task_restart` (`execute_restarted_task`), appends `task_id` to `WorkspaceProfile.linked_tasks`, and marks interrupted tasks on shutdown.

## Granular Per-Project & Per-Client Permissions
Each workspace defines default permissions (`read`, `write`, `delete`, `execute`, `git`), defaulting to read-only (`read=True`, everything else `False`), plus optional `client_permissions[client_id]` overrides, `allowed_clients`, and `min_profile`.

## Windows Path Security & Honest Boundaries
- **Canonical Resolution & Reparse Protection**: Rejects `..` traversal, absolute paths, UNC paths (`\\server\share`), device prefixes (`\\?\`, `\\.\`), Windows reserved names (`CON`, `NUL`, `COM1..9`, etc.), NTFS Alternate Data Streams (`:`), `.git`, `.env*`, key/certificate suffixes, symlinks, and Windows NTFS junctions (`FILE_ATTRIBUTE_REPARSE_POINT`) at every path segment.
- **Opened-Handle Verification**: After opening a file descriptor, `verify_opened_fd` re-verifies the actual OS handle target via `GetFinalPathNameByHandleW` on Windows or `(st_dev, st_ino)` `fstat`/`lstat` matching on POSIX.
- **Optimistic Version Precondition**: Modifying existing files (`workspace_write_file`, `workspace_apply_patch`, `workspace_delete_file`) requires matching `expected_sha256` to prevent clobbering concurrent user edits. All writes are atomic and save local rollback snapshots (`WorkspaceHistory`).
- **Untrusted Git Hooks Suppressed**: When `trust_git_hooks` is `False` (default), Git commands run with empty `core.hooksPath`, disabled `fsmonitor`, `credential.helper`, `ext::`, and filters, plus `--no-verify` on `git commit`.
- **Honest Boundary**: Specialized `workspace_*` and `git_*` tools enforce these guards fail-closed. **Full Access CMD/PowerShell (`oauth_windows_command` with `full` profile) is NOT sandboxed** and runs with the current OS user's full privileges.

## Workspace Addition Wizard & Bounded Discovery (`N04`)
- **4-Step Guided Flow (`app/ui/workspace_wizard.py`)**: Inside **Workspaces** (no new top-level tab; manual `WorkspaceProfileDialog` preserved in `⋯` and via `"Manual Form…"`), owners follow **Directory → Analysis → Proposals → Access & Review** using a non-blocking background `QThread` with cooperative cancellation and stale-result rejection on root changes.
- **Strictly Static Read-Only Discovery (`backend/workspaces/discovery.py`, `compose_yaml.py`, `manifest_policy.py`)**:
  - Uses lazy `os.scandir` BFS and segment-by-segment glob traversal with a single unified resource budget (`DiscoveryLimits`: `max_depth=3`, `max_entries=400`, `max_manifest_bytes=128 KiB`, `max_total_bytes=1 MiB`, `max_seconds=5.0`) across parent scan, monorepo subprojects, and manifest hashing (zero full `iterdir`/`glob` materialization or unbounded sorting); surfaces truncation diagnostics cleanly.
  - Rejects broad/system/network roots (`C:\`, `/`, `$HOME`, `%APPDATA%`, `DRIVE_REMOTE`, UNC/ADS/device paths), skips excluded directories (`node_modules`, `.git`, `.venv`, `build`/`dist`/cache, secret dirs) and reparse/symlink segments at every glob step, rejects FIFOs/special/device files via pre-open `os.lstat` (`S_ISREG`) and `O_NOFOLLOW | O_NONBLOCK`, re-verifies every opened file descriptor via `verify_opened_fd`, and never runs project binaries, package installs, or network requests.
  - Supports **Python** (`pyproject.toml` via `tomllib`, `requirements*.txt` package names only, `.venv`/`venv` structure, FastAPI/Flask/pytest/unittest), **Node.js / TypeScript / Next.js / Vite / Express** (strict duplicate-key JSON `package.json`, lockfiles, `packageManager`, `tsconfig.json`, exact provable scripts with lifecycle-hook warnings), **Docker Compose** (bounded custom safe YAML parser rejecting tags/anchors/aliases/duplicate keys/external `include`/`extends` and never expanding `${VAR}` or reading `.env`/`environment` values), **Git** (non-reparse `.git/` boundary check without climbing above user-selected scope or reading `.git/config`), **monorepos** (bounded `package.json#workspaces`, `pnpm-workspace.yaml`, `pyproject.toml` `[tool.uv.workspace]`), and **unknown/empty** folders (manual mode).
  - Scrubs URL credentials and secret-bearing commands (`redact_discovery_text`, `_command_has_secret_material`) and uses `_trusted_system_which` outside the analyzed project root so local `node.exe`/`python.exe` inside untrusted repositories are ignored.
- **Deny-by-Default OAuth, Significant Manifest Set & Unified Re-Approval (`N04`)**:
  - New workspaces default to `permissions = read=True, write=delete=execute=git=False`, `trust_git_hooks=False`, `manifest_guarded=True`, and `allow_oauth_clients=False` (explicitly separate from empty `allowed_clients` so legacy profiles remain backwards-compatible while new workspaces deny all OAuth clients until the owner opts in).
  - Proposed `ServerProfile`s default to `workspace_scoped=True`, `autostart=False`, `expose_externally=False`, zero secrets, and stamped `wizard_managed_workspace_id` + `manifest_guarded=True` metadata; existing manual/shared/foreign servers are never modified or auto-linked by `cwd`/name.
  - Atomic commit (`WorkspaceServerCoordinator.commit_workspace_addition`) runs inside `.n03_coordinator_tx.json` WAL rollback with case-insensitive ID/name, canonical root duplicate/alias, nested-monorepo acknowledgement, stale-plan fingerprint, root identity, and significant-manifest digest checks.
  - `verify_manifest_digests` checks a bounded, documented stack manifest set (`SIGNIFICANT_MANIFEST_FILES`: `package.json`, Node lockfiles/rc configs/TS/Next/Vite configs, `pyproject.toml`/`setup.py`/`setup.cfg`/Python lockfiles/`pip.conf`/`pip.ini`/`pytest.ini`/`tox.ini`/`conftest.py`/`requirements*.txt`, Compose files + overrides, `Cargo.toml`/`Cargo.lock`/`go.mod`/`go.sum`) for modification, deletion, and unexpected additions (without hashing general source code or promising OS sandboxing / Full Access alteration). `WorkspaceStore.upsert_workspace` and `ServerConfigStore.upsert_profile` refuse stripping `manifest_digests` / `manifest_guarded`.
  - Both `WorkspaceManager` (initial auth and `pre_dispatch_check` right before subprocess spawn) and `ServerManager` (`_launch_single` + `_pre_spawn`) enforce fail-closed manifest verification. On drift, GUI opens `ManifestReapprovalDialog` (`app/ui/manifest_reapproval_dialog.py`) showing redacted manifest diffs, command/runtime/server diffs, lifecycle warnings, and effective permissions bound to a `WizardPlanSnapshot` (capturing registry state, root identity, `manifest_digests`, plus `proposal_fingerprint` / `plan_fingerprint` over proposed commands, runtime/venv, `node_path`, `git_root`, server proposals, linked profiles, and decision-affecting warnings); both `commit_workspace_addition` and `commit_manifest_reapproval` reject unseen changes with `WizardStalePlanError` (zero writes) and commit strictly from the exact approved snapshot via `_run_tx`, leaving manual/shared/foreign servers untouched and keeping command/runtime/server-param updates opt-in. Once `execute=True` and manifests match, no extra confirmation prompts are added.
